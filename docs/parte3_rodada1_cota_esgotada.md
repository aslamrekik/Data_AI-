# Parte 3 — Primeira execução real do extrator (rodada interrompida)

> **Leia isto antes dos números abaixo.** Este é o relatório da primeira execução
> real do extrator com a API do Gemini, em 27/09/2026. Ele foi guardado como registro
> histórico, e não como resultado final da Parte 3. O resultado final está em
> `parte3_laudos/saida/avaliacao.md`.

## O que aconteceu

- O modelo estava sobrecarregado e devolveu **erro 503** nos laudos 01, 02 e 08.
  O extrator tentou 3 vezes cada um.
- Essas tentativas repetidas gastaram a **cota gratuita do Gemini: 20 requisições
  por dia, por projeto e por modelo**. Do laudo 07 em diante, todas as chamadas
  voltaram com **erro 429** (cota esgotada).
- Além disso, a execução completa **sobrescreveu** o `extracoes.json` com as falhas,
  apagando testes anteriores que tinham dado certo (laudos 01 e 02).

## Como ler os números

Só **4 de 17 laudos** foram extraídos: 03, 04, 05 e 06.

| Métrica | Valor | O que significa |
|---|---|---|
| Acurácia total | 21,3% (58 de 272 campos) | Mede quantos laudos a API conseguiu responder, não a qualidade do extrator. Os 13 laudos que falharam contam como falha. |
| Acurácia nos 4 laudos extraídos | 90,6% (58 de 64 campos) | É o número que mede o extrator. |
| Alucinações | 0 | Nenhum valor inventado. |
| Erros de valor | 0 | Nenhum valor extraído estava errado. |
| Abstenções | 6 | O Gemini citou como evidência só o valor ("SP", "2018"), e não a linha do laudo. A checagem de evidência recusou esses campos, embora os valores estivessem certos. |

Nos laudos que respondeu, o extrator não chutou nada. Quando errou, errou para o
lado seguro.

## O que isso motivou

| Problema | Correção | Commit |
|---|---|---|
| Tentativas repetidas gastavam a cota diária | Cota diária esgotada passa a encerrar a execução na hora; erros temporários (503, 429 por minuto) esperam o tempo que a própria API indica, com no máximo 2 tentativas | `10e6866` |
| Uma rodada com falhas apagava resultados bons | Uma extração bem-sucedida nunca é sobrescrita por uma falha; a opção `--pendentes` extrai só os laudos que faltam | `10e6866` |
| Evidência curta demais gerava abstenções desnecessárias | O prompt pede a linha inteira do laudo. Se o Gemini citar só o valor, o código procura no laudo a única linha que contém o valor e fala do campo, e registra que a evidência foi localizada pelo código | `ff21aca` |
| Falha da API se confundia com erro do extrator | O relatório passa a mostrar a acurácia nos laudos extraídos ao lado da acurácia total | `d6ed605` |

A lição: nenhum dos testes simulados pegou esses problemas. Eles só apareceram numa
execução real, com a API falhando de verdade.
